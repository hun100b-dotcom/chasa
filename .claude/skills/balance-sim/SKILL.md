# balance-sim — 밸런스 QA 절차 (qa-balance-lead)

> 목표 문장: "적이 몰려 있으면 파혼이 유리하고, 여유가 있으면 천도가 유리하다." 이 **뒤집힘**이 깨지면 기둥 1이 무너진다.

## 1. 입력은 항상 `data/balance.json` + `docs/harness/LOCKED-DECISIONS.md`
- 시뮬레이터는 코드와 **같은 JSON**을 읽는다(숫자 복사 금지 → 코드와 시뮬이 어긋나는 사고 방지).
- 값 변경 순서: LOCKED-DECISIONS → balance.json → 시뮬 재실행 → 보고.

## 2. 방법 (작은 팀에서 검증된 순서)
1. **한 번에 변수 1~2개만** 바꾼다. 기준선(baseline)을 항상 같이 돌려 비교한다.
2. **몬테카를로**: 시드 고정(재현) × 최소 1,000판. 평균만 보지 말고 **분포(10/50/90 백분위)** 를 본다.
3. **정책 3종 대결**: (a) 항상 천도 (b) 항상 파혼 (c) 상황 적응형(적 수·체력·업 기준). 
   - 판정: (c)가 (a),(b) 모두를 이기는 구간이 존재해야 선택이 성립.
4. **랜덤 에이전트 대조**: 아무렇게나 고르는 정책이 (c)와 비슷하면 → 운 지배 구간(선택이 무의미). 학술 사례에서도 난이도 급등/운 지배 판별에 쓰는 표준 점검.
5. **불변식(invariant) 검사** — 어느 상태에서도 참이어야 하는 것:
   - 연속 천도 0.8초 연쇄가 무한 이득이 되지 않는다(상한/쿨다운 존재).
   - 업은 0 미만이 되지 않는다. 업 감쇠(천도 2회 −1)가 결말 A 조건(업 60 미만)을 달성 가능하게 한다.
   - 명부 미달 패널티는 성장 손실로 번지지 않는다(기둥 3).
   - 덩어리만 나오는 구역에서도 업 폭주를 피할 길이 있다.
6. **민감도 표**: 핵심 상수 ±20% 흔들었을 때 결과가 어떻게 바뀌는지(어느 숫자가 지렛대인지) 한 표로.
7. 가능하면 **사람 플레이 몇 판과 방향이 같은지** 대조(시뮬이 현실과 다른 방향이면 시뮬을 의심).

## 3. 산출물 형식
- 스크립트: `tools/sim/` (시드·입력 파일 경로를 인자로, 결과는 JSON+표). 스크립트도 커밋.
- 보고(채팅 본문): `구간 | 천도 우세 조건 | 파혼 우세 조건 | 뒤집힘 유지? | 위험` 표 + 핵심 3줄 + "임시 가정값" 명시.
- 실측 전 숫자는 **전부 임시값**이라고 적는다. 느낌 말고 숫자로.

## 4. 흔한 함정
- 평균 이득만 비교 → 위험(피격) 분산을 놓친다. 반드시 분포.
- 시뮬 보상 함수 하나로 "재미"를 판단하지 않는다. 시뮬은 **깨진 곳 찾기** 도구, 재미는 오너 플레이가 판정.
