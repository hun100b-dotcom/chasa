# P1-016 크로스플랫폼 입력 추상화 (설계 1차)

> 목적: PC 마우스·키보드와 모바일 터치를 **같은 "명령"**으로 바꿔 주는 중간 계층. 게임 규칙(플레이어·적)은 "누른 방법"을 모르고 명령만 받는다.
> 근거: VISION/COMBAT-SPEC 1-3·1-4, PD 피드백(2026-10-24: 마우스 = 이동·타겟, 키보드 = 기술), `godot/main.gd`·`player.gd`에서 실제로 검증된 구조. **"입력이 헷갈리면 안 된다"**(TASKS).

## 1. 명령(Command) 목록 — 규칙 쪽이 아는 것은 이것뿐
| 명령 | 인자 | 플레이어 쪽 함수(Godot판 이름) |
|---|---|---|
| Move | 바닥 위치 | `command_move` |
| Attack | 대상 적 | `command_attack` (콤보 이음) |
| Swing | 조준 위치 | `command_swing` (제자리 휘두르기) |
| Pull | 대상 적 / 조준 위치 | `command_pull` (견인) |
| Tendo | 무릎 꿇은 혼 | `command_tendo` (천도) |
| Pahon | 무릎 꿇은 혼 | `command_pahon` (파혼) |

## 2. 입력 → 명령 대응
| 명령 | PC | 모바일(터치) |
|---|---|---|
| Move | 바닥 좌클릭(누른 채 끌면 따라 걷기) | 바닥 탭 |
| Attack | 적 좌클릭 | 적 탭 |
| Swing | Space (커서 방향) | SWING 버튼 (가장 가까운 적 방향) |
| Pull | Q 또는 우클릭 | PULL 버튼 (가장 가까운 적) |
| Tendo | 무릎 꿇은 혼 **길게 누름(0.3초)** 또는 E | 롱탭 또는 SEND 버튼 |
| Pahon | 무릎 꿇은 혼 **짧게 클릭** 또는 R | 탭 또는 SHATTER 버튼 |

핵심 규칙: **무릎 꿇은 혼을 누르면 "공격"이 아니라 "처결 입력"으로 해석**한다(길이로 천도/파혼 구분). 길게 눌러 천도가 시작되면 손을 떼도 캐스팅은 이어진다(짧은 클릭으로 오인 방지, 검사로 확인됨).

## 3. 계층 구조 (엔진 무관)
```
[장치 입력: 마우스·키보드·터치]  →  [해석기 InputInterpreter]  →  [Command]  →  Player.command_*()
                                      ↑ 화면 → 바닥 좌표 변환, 대상 고르기(pick), 누름 길이 재기
```
- 해석기만 플랫폼별로 다르다(PC용 / 터치용). 명령 이후는 공유.
- **대상 고르기**: 몸에 직접 맞으면 우선, 아니면 클릭 지점 근처 가장 가까운 적(관대한 판정). 터치는 손가락이 가려서 반경을 더 크게(🔴 값은 폰 실측으로).
- **터치는 커서가 없다** → 기술 버튼은 "가장 가까운 적/혼"을 자동 선택(구현됨: `_touch_skill`).

## 4. Unity 이식 방침
- Unity Input System의 Action Map 두 벌(PC·Touch) → 같은 `Command` 이벤트로 변환.
- `unity/Assets/Scripts/GameMain.cs`의 입력 부분을 해석기 클래스로 분리(지금은 Godot판 1:1 포팅).
- 게임패드·키 리바인딩은 Phase 2.

## 5. 검증 체크(예/아니오)
1. 같은 상황에서 PC와 모바일이 같은 결과를 내는가 (명령 로그 비교).
2. 길게 누름 0.3초 임계가 모바일에서 오입력(이동↔처결)을 만들지 않는가 — 🔴 폰 실측.
3. 손가락으로 무릎 꿇은 혼을 고르기 쉬운가(판정 반경) — 🔴 실측.
