## 1. 평가 기준과 가중치

| 기준 | 가중치 | 왜 이 비중인가 |
|---|---|---|
| A. AI 직접 개발 적합도 | 25% | 오너는 코드·에디터를 만지지 않는다. Claude가 텍스트 파일만으로 수정·빌드·테스트까지 끝낼 수 있어야 1인 비전공 개발이 성립한다. |
| B. PC + 모바일 출시 | 20% | 확정 사항. 스토어(안드로이드·iOS) + PC(스팀) 네이티브 빌드가 가능한가. |
| C. 쿼터뷰 액션 손맛 | 15% | 히트스톱·넉백·물리·애니메이션 제어. 디아블로식 타격감의 바탕. |
| D. 시네마틱·다이내믹 카메라 | 15% | 확정 사항. 컷신 타임라인, 카메라 연출 도구. |
| E. 다크 고딕 비주얼 품질 | 10% | 조명·안개·후처리. 천도 중 "시야 60% 축소" 연출도 여기. |

### 점수 근거 (핵심만)

- **Godot** — 씬·리소스가 전부 사람이 읽는 텍스트(.tscn/.tres)라 AI가 직접 편집 가능. **2026-10-24 이 클라우드 컨테이너에서 Godot 4.7.2를 내려받아 헤드리스(화면 없이)로 스크립트 실행까지 확인** → Claude가 빌드·내보내기를 오너 없이 할 수 있다. PC·안드로이드·iOS·웹 내보내기 내장. 네이티브는 Forward+ 렌더러(볼류메트릭 안개, SDFGI 전역 조명). AnimationPlayer로 카메라·캐릭터·이벤트를 한 트랙에 묶어 컷신 제작 가능(전용 시퀀서는 없음 → D 4점). MIT 라이선스, 비용 0.
  - 약점: **웹 빌드는 Compatibility(WebGL2) 렌더러만** 써서 네이티브보다 화면이 수수하다. C#은 웹 내보내기 불가 → GDScript로 간다. 빈 웹 빌드 약 5MB(Brotli). 4.3부터 단일 스레드 웹 내보내기로 iOS 사파리 문제 해소.
- **Unity** — 모바일·시네마틱(Timeline + Cinemachine)·에셋스토어는 업계 최고. 그러나 씬·프리팹 편집은 사실상 에디터 GUI 작업이고, 클라우드에서 돌리려면 라이선스 활성화·수 GB 에디터 설치가 필요 → A 2점. Personal은 최근 12개월 매출·투자 20만 달러 미만 무료, 초과 시 Pro(1석 연 2,310달러). 웹 빌드는 빈 3D 기준 약 10.7MB, WebGPU는 6.6에서 정식 지원.
- **Babylon.js** — 웹 3D 엔진 중 기능이 가장 두껍다(9.0: 수백 개 동적 조명용 클러스터드 라이팅, 볼류메트릭 조명). 순수 코드라 AI 친화적. 하지만 **게임 엔진이 아니라 렌더러에 가까워** 씬 편집·애니메이션 타임라인·스토어 출시를 직접 조립해야 한다(앱 포장은 Capacitor 같은 래퍼 필요).
- **Three.js (현재)** — 손맛 프로토타입에는 최적이었다. 다만 컷신 도구·애니메이션 리타게팅·모바일 스토어 출시·저장/인벤토리 UI를 전부 손으로 짜야 한다. 액션 RPG 본편 규모에서는 "엔진을 직접 만드는" 일이 된다.
- **Unreal 5** — 비주얼·시네마틱 최강이지만 에셋이 바이너리(.uasset)라 AI가 못 고치고, 웹 출시 불가, 모바일은 무겁다. 1인 비전공 + AI 개발 구조와 정면 충돌 → 제외.
- **PlayCanvas** — 웹 품질은 좋지만 클라우드 에디터(GUI) 중심이고 비공개 프로젝트는 유료 플랜. 엔진만 코드로 쓰면 Babylon과 같은 약점.

## 3. 추천안

### 1순위: **Godot 4.7 (GDScript)** — 가중 4.20

이유 세 줄:
1. **오너가 아무것도 안 눌러도 Claude가 끝까지 만든다.** 텍스트 씬 + 헤드리스 빌드(실측 확인). Unity는 이 지점에서 매번 막힌다.
2. **스토어 출시까지 한 엔진으로 간다.** 웹 엔진들(Three/Babylon/PlayCanvas)은 앱 포장·성능 최적화를 따로 해결해야 한다.
3. **비용·정책 위험 0.** MIT 오픈소스라 가격 정책이 바뀔 일이 없다.

### 2순위: **Unity 6.6** — 가중 3.95
선택 조건: 앞으로 **사람 개발자(특히 Unity 경력자)를 채용**하거나, 컷신 비중이 압도적으로 커질 때. 이때는 A 기준의 가중치가 내려가 Unity가 1위가 된다.

### 3순위(조건부): **Babylon.js 9** — 가중 3.70
선택 조건: "스토어 출시보다 **웹 링크 배포가 본업**"으로 방향을 바꿀 때.

## 4. Godot 채택 시 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 웹 빌드 화질이 네이티브보다 낮음 | 폰 링크 플레이테스트가 실제보다 수수해 보임 | 웹 링크는 "손맛·밸런스 확인용", 화질 확인은 안드로이드 APK 빌드로 분리 |
| 전용 시네마틱 시퀀서 없음 | 컷신 제작 손이 더 감 | AnimationPlayer 트랙 + 카메라 연출 스크립트를 공용 도구로 1회 제작 |
| 단계 0 프로토타입(Three.js) 이식 필요 | 1~2 작업 세션 | 코드 약 9파일·도형만이라 소규모. `config.ts` 손맛 값은 그대로 옮겨 같은 느낌인지 비교 |
| C# 웹 미지원 | 언어 선택 제약 | GDScript 사용(파이썬과 비슷, AI 작성 품질 높음) |
