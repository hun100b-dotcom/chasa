# 기술 부채 정리 설계: 화면(UI)과 전투 손맛 구조 (QA·코드)

> 설계 문서만 있다. 코드는 아직 안 바꾼다. 「도깨비의 세계」 격차 분석이 나오면 우선순위를 다시 잡는다. (2026-10-24, 코디네이터 지시)

## 0. 지금 상태 (사실)
- 화면 글자·버튼·창은 전부 **IMGUI**(OnGUI, 코드로 매 프레임 그리는 옛 방식). 해상도마다 위치를 손으로 계산한다.
- 전투 손맛(히트스톱·흔들림·숫자)은 `Player.HitEnemy` 안에서 `feel.HitStop(...)`, `feel.AddShake(...)`, `numbers.Spawn(...)`을 **직접 부른다**. 값은 `ComboStep` 표에 묶여 있다.
- 그림은 2장 번갈아 보이기(걷기)와 상태별 한 장(공격·맞음)이 전부다. 애니메이션 시스템이 없다.
- 소리가 없다. 카메라는 고정 각도에 흔들림만 있다.

## 1. UI: 무엇으로 옮길까

| 후보 | 장점 | 약점 |
|---|---|---|
| **UI Toolkit(UXML/USS 텍스트 파일)** | 화면이 **글자 파일**이라 에디터 없이 AI가 만들고 고칠 수 있다. 플렉스 레이아웃이라 폰·PC 해상도가 저절로 맞는다. 테마(색·글꼴)를 USS 한 곳에서 바꾼다 | 월드 공간(적 머리 위 이름표·피해 숫자)에는 부적합, 한글 글꼴 에셋(SDF)을 에디터 스크립트로 만들어야 한다 |
| uGUI + TextMeshPro | 자료 많고 WebGL에서 오래 검증됨 | 장면·프리팹(에디터에서 만드는 상자) 중심이라 오너·AI가 에디터 없이 다루기 번거롭다. 코드로만 만들면 길고 지저분하다 |
| IMGUI 유지 | 지금 동작 | 겹침·정렬 버그가 계속 난다(QA B2), 애니메이션·접근성 없음 |

**권고: 화면 UI(HUD·결과·캐릭터 창·낮·서낭당)는 UI Toolkit, 월드 위 글자(피해 숫자·이름표)는 TextMeshPro 월드 텍스트 또는 지금처럼 코드로 그리기.**
이유: (1) 이 프로젝트는 에디터 손작업 없이 파일만 바꿔 개발한다 → UXML/USS가 맞다. (2) 레이아웃이 자동이라 B2 같은 겹침이 구조적으로 줄어든다. (3) 폰 세로·가로 대응이 쉽다.

한글 글꼴: 지금 `Resources/Fonts/NotoSansKR-Subset.ttf`(0.4MB, 2350자). UI Toolkit은 **FontAsset(SDF)**이 필요하므로 PC 숨김 배치 모드 에디터 스크립트 한 개(`FontAssetBuilder`)로 만들고 **Dynamic(없는 글자는 그때 추가)**로 둔다. 글꼴에 없는 글자가 나오면 네모가 되므로 글자 점검 도구(`tools/check_glyphs.py`)를 CI처럼 푸시 전에 돌린다.

### 이전 단계 (각 단계가 끝나면 게임은 항상 돌아간다)
1. **U0 토대**: PanelSettings(스케일 기준 1280×720, 폰은 Scale With Screen Size), 글꼴·색 토큰 USS(`theme.uss`: 팔레트는 `ChasaPalette`와 같은 값), `UiRoot` 스크립트 1개.
2. **U1 HUD**: 체력·넋·기억·엽전·업·무기·도술 칸·밤 시계·몫 진행. `JudgeSystem`이 직접 글자를 만들지 않고 `HudState`(순수 C# 값 묶음)만 갱신 → 화면은 그 값을 읽는다. 값 묶음은 Core 쪽 테스트 가능.
3. **U2 결과·낮·서낭당·캐릭터 창**: 현재 IMGUI 4개를 하나씩 대체. 캐릭터 창은 탭 3개를 USS 탭으로.
4. **U3 터치**: 큰 버튼 영역·엄지 위치, `Ko.TouchUI` 감지 유지.
5. **U4 IMGUI 제거**: 디버그 표시(?debug)만 남기거나 삭제.
- 각 단계 확인: 클라우드 컴파일 검사 + PC 숨김 WebGL 빌드 + 스크린샷(겹침·네모 글자 눈으로).
- 위험: UI Toolkit 런타임 WebGL 성능은 가볍지만 **글꼴 에셋 생성이 PC 작업**이라 배치 한 번이 필요하다.

## 2. 전투 손맛 구조

### 2-1. 문제
타격 한 번에 일어나는 일(멈춤·흔들림·숫자·번쩍임·밀림·소리·이펙트)이 호출부에 흩어져 있어, **새 무기·적·도술마다 같은 줄을 복사**하게 되고 값을 한 곳에서 조율할 수 없다.

### 2-2. 설계: 전투 사건 → 손맛 프로필 → 반응기
```
CombatEvent { 종류(Hit/Kill/Hurt/Cast/Pahon/Tendo…), 공격자, 대상, 피해량, 위치, 방향, 무기Id, 콤보단계 }
   └─ CombatEvents.Raise(evt)                      ← 전투 코드는 이것만 부른다
        ├─ FeelProfile 조회(종류+무기+단계)         ← data/feel.json (엔진 무관, balance.json 과 같은 규칙)
        └─ 반응기들이 각자 프로필 값을 읽어 실행
             HitStop · CameraImpulse · DamageNumbers · Flash/Squash · Knockback · SfxPlayer · VfxSpawner · Rumble(폰 진동)
```
- `data/feel.json` 예: `{"mace.3": {"hitstop":6,"shake":1.0,"zoomPunch":0.04,"flashMs":140,"sfx":"mace_slam","vfx":"ring_dust","slowmoOnKill":0.12}}`
- 새 무기·적은 **프로필 한 줄**만 추가. 값 조율은 JSON 한 곳(오너 말 "히트스톱 더"가 곧 JSON 한 칸).
- 반응기는 서로 모른다 → 하나 끄고 켜서 손맛 요소별 비교(A/B)가 쉽다.

### 2-3. 히트스톱·카메라
- **히트스톱을 전체 시간정지가 아니라 '행위자 국소 정지'**로: 때린 플레이어·맞은 적만 `localTimeScale=0` 몇 프레임, 나머지(다른 적·이펙트)는 계속. 지금 전체 정지는 다수전에서 "끊기는 느낌"이 난다.
- 카메라: `CameraImpulse`(방향성 있는 흔들림, 감쇠 스프링) + 줌 펀치(FOV 몇 %) + 처치 시 짧은 슬로모(0.1초, 배율 0.3). 지금은 방향 없는 무작위 흔들림 한 종류.
- 예고 연출: 적 공격 예비동작에 **예고 표시(바닥 호·몸 부풀기)**와 **0.4초 안에 피할 수 있다는 신호**를 분리(접근성: 색만 쓰지 않기).

### 2-4. 애니메이션
- 지금 `ActorSprite`의 "상태별 한 장"을 **스프라이트 시트 애니메이터**(상태 + 프레임 시간표 + **프레임 이벤트**)로 확장: idle/walk/attack(예비·타격·후딜)/hurt/kneel/death.
- **타격 판정을 프레임 이벤트에 묶기**: "타격 프레임에서만 판정"이면 시각과 판정이 항상 맞는다(지금은 스윙 각도로만 판정).
- 아트가 시트를 주기 전까지는 기존 한 장 + **스쿼시·스트레치·기울임을 코드로** 주는 임시 애니메이터(비용 작고 손맛 효과 큼). 위치: `ActorAnimator.cs`(새 파일), `Player/Enemy`는 상태만 알려 준다.

### 2-5. 소리
- 에셋 없이 시작: 코드 합성(짧은 노이즈·사인 감쇠)으로 **타격·천도 캐스팅·파혼·단서·UI** 임시음 8개. 이후 라이선스 확인된 음원으로 교체(`sfx` id만 유지).
- 천도 캐스팅은 "소리가 줄어드는 연출"(시야 축소와 짝)을 믹서 낮은 통과 필터로.

### 2-6. 단계와 확인
| 단계 | 내용 | 확인 |
|---|---|---|
| F0 | `CombatEvents` + `FeelProfile`(JSON 로더, Core 테스트) 도입, 기존 호출 3곳을 이벤트로 교체(동작 동일) | EditMode 테스트 + 같은 수치로 화면 동일 |
| F1 | 국소 히트스톱·카메라 임펄스·줌 펀치 | PC 스크린샷 시퀀스로 흔들림 비교(수치 로그 병행) |
| F2 | `ActorAnimator`(코드 애니메이션)와 프레임 이벤트 판정 | 타격 프레임 로그 = 판정 프레임 일치 테스트 |
| F3 | 임시음 8개 | 소리는 PC에서 오너가 듣는 확인만 가능 — 소리 켜기/끄기 버튼 필수 |
| F4 | 시트 애니메이션으로 교체(아트 납품 시) | 상태 전이 표 테스트 |

### 2-7. 리스크
- 손맛은 **숫자로 못 재는 부분**이 크다 → 영상(GIF) 비교 + 오너 체감 한 줄 피드백을 기준으로 하되, 프로필 값 변경 이력을 `docs/progress.md`에 남긴다.
- 헤드리스 확인으로는 소리·체감이 안 보인다 → 오너가 "게임 끝"일 때만 PC 검증.
- IP: 레퍼런스 게임의 연출 수치를 그대로 베끼지 않는다. 기준은 "내 게임에서 때리는 맛이 나는가"이고 값은 우리 JSON에서만 정한다.

## 3. 우선순위 제안 (격차 분석 전 잠정)
1. F0·F1(구조 + 국소 히트스톱·카메라) — 비용 작고 효과 큼.
2. U0·U1(HUD) — 겹침 버그 구조적 제거.
3. F2(코드 애니메이션 + 프레임 이벤트 판정).
4. U2~U4, F3, F4.
