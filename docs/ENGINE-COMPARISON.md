## 0. 조건 (TASKS.md P1-001)
PC + 모바일 크로스 플랫폼 / 화면에 적 다수가 떠도 버티는 성능 / 실시간 시네마틱 컷신·다이내믹 카메라 /
1인 비전공 개발 — 학습 곡선과 라이선스. 그리고 이 프로젝트의 실제 작업 방식:
**PD는 코드·에디터를 만지지 않고, Claude가 파일을 직접 고치고 빌드한다.**

## 3. 항목별 근거

**① 모바일 성능·발열** — Unity는 모바일 최적화 도구(프로파일러, URP 모바일 설정, 적응형 성능)가 업계 표준. Godot는 네이티브 앱에서 Vulkan 기반 Mobile 렌더러를 쓰며 준수. 웹 엔진 3종은 모바일 **브라우저** 안에서 돌아 발열·배터리 손해가 크고 앱 출시엔 Capacitor 같은 포장 도구가 따로 필요. Unreal은 모바일에서 무겁다.

**② 적 다수 처리** — Unity는 DOTS/ECS(수천 개 개체를 묶어 빠르게 처리하는 구조)가 있다. Godot는 GDScript가 느린 편이라 적이 수백 단위가 되면 MultiMesh(같은 모양을 한 번에 그리기)·서버 API·일부 C++(GDExtension) 최적화가 필요. 웹 엔진은 인스턴싱으로 그리기는 되지만 로직이 JS 단일 스레드에 묶인다.

**③ 쿼터뷰 액션 레퍼런스** — 쿼터뷰 ARPG 여러 편(유니티·언리얼 사례 다수, 고도는 3D 대작 사례가 아직 적음). 웹 엔진: 상업 ARPG 사례 사실상 없음.

**④ 라이선스·로열티** — Godot·Three·Babylon: MIT, 완전 무료·로열티 없음. Unity: Personal은 최근 12개월 매출+투자 20만 달러 미만 무료, 초과 시 Pro(1석 연 2,310달러, 2026-01 인상 반영). 2023년 런타임 수수료 사태는 2024-09 철회됐지만 정책 변경 이력이 리스크. Unreal: 매출 100만 달러 초과분 5% 로열티. PlayCanvas: 비공개 프로젝트는 유료 플랜.

**⑤ 에셋 스토어** — Unity 에셋스토어가 압도적(카메라·컷신·최적화 도구까지). 단, 단계 0 원칙상 에셋은 손맛 검증 뒤라 당장 영향은 작다. Godot Asset Library는 무료 위주·소규모.

**⑥ 비전공자 난이도** — Godot는 엔진이 가볍고(설치 약 80MB) 개념이 단순. Unity는 기능이 방대해 메뉴·설정이 많다. Unreal은 가장 어렵다. 웹 엔진은 에디터 없이 순수 코드라 비전공자가 직접 볼 화면이 없다(AI가 다 해야 함).

**⑦ 한국어 자료량** — Unity가 압도적(책·강의·커뮤니티). Unreal도 국내 대형사 덕에 풍부. Godot는 최근 빠르게 늘지만 아직 중간. 웹 엔진은 한국어 자료가 드물다.

**⑧ 컷신·카메라 툴** — Unity: Timeline(컷신 편집기) + Cinemachine(자동 카메라 연출) 내장, 업계 최고 수준. Unreal: Sequencer, 최고 수준. Godot: AnimationPlayer 하나로 카메라·캐릭터·이벤트를 트랙에 묶어 컷신 제작 가능하나 전용 시퀀서·자동 카메라 도구는 없음(직접 1회 제작 필요). Three.js: 컷신 도구 없음, 전부 손으로.

**⑨ AI 코딩 궁합** — Godot: 씬·리소스가 사람이 읽는 텍스트 파일(.tscn/.tres)이라 AI가 직접 편집 가능. **실측: 2026-10-24 클라우드 작업 환경에 Godot 4.7.2를 내려받아 헤드리스(화면 없이) 실행 성공** → AI가 PD 개입 없이 빌드·내보내기 가능. Unity: 스크립트(C#)는 AI가 잘 쓰지만 씬·프리팹 배치는 사실상 에디터 GUI 작업이고, 자동 빌드엔 라이선스 활성화·수 GB 에디터 설치가 필요. Unreal: 에셋이 바이너리(.uasset)라 AI가 못 고친다. Babylon·Three: 순수 코드라 최상(현재 프로토타입이 그 증거).

## 5. 추천 2안 (결정은 PD)

### 안 A — Godot 4.7 (GDScript) · 가중 4.15
- **이 안을 고르면:** AI가 처음부터 끝까지 혼자 만들고 빌드한다. 비용 0, 정책 리스크 0. PC·모바일 네이티브 + 웹 테스트 링크를 한 엔진으로.
- **대가:** 컷신 도구와 적 대량 처리 최적화를 직접 만들어야 한다. 웹 링크 화질은 네이티브보다 수수(화질 확인은 안드로이드 빌드로).
- **이식 비용:** 단계 0 프로토타입(약 9파일, 도형만) → 1~2 작업 세션. `config.ts` 손맛 값을 그대로 옮겨 같은 느낌인지 비교.

### 안 B — Unity 6.6 (URP, C#) · 가중 3.85
- **이 안을 고르면:** 모바일 성능·적 대량 처리·컷신·에셋·한국어 자료가 전부 최상급. 앞으로 사람 개발자를 채용하면 바로 합류 가능.
- **대가:** 씬 배치·빌드 설정에서 에디터 GUI 작업이 반복적으로 생긴다(PD가 직접 누르거나 Unity 경험자가 필요). 매출 20만 달러 초과 시 유료.
- **판단 기준:** "1년 안에 Unity 경력자를 들일 계획이 있다" 또는 "컷신이 게임의 핵심 비중"이면 B가 유리.

### 제외 사유 (한 줄씩)
- Unreal: AI가 에셋을 못 고치고 웹 불가, 모바일 무거움 → 1인 AI 개발 구조와 충돌.
- Babylon / Three: AI 궁합은 최상이나 게임 엔진 기능(컷신·스토어 출시·모바일 성능)을 전부 직접 조립해야 함. Three는 단계 0 손맛 검증용으로는 계속 유효.
- PlayCanvas: 클라우드 GUI 에디터 중심 + 비공개 유료.
