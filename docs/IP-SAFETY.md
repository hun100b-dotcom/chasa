# IP-SAFETY — 저작권 안전선

> **이 문서가 왜 존재하는가**
> `IP(Intellectual Property — 지식재산권. 남이 만든 캐릭터·이름·그림·설정에 대한 권리)`
>
> 1인 개발에서 저작권 분쟁은 **게임을 못 만들게 되는 사고**다. 소송에서 이기든 지든,
> 그 과정에 들어가는 시간과 돈을 1인 개발자는 감당할 수 없다.
> 그래서 **분쟁이 날 여지 자체를 만들지 않는다.** 이 문서는 그 경계선이다.
>
> ⚠️ **아트 리드(`visual-art-lead`)는 이 문서를 근거로 작업 거부권을 행사한다.**
> "오너가 요청했으니까"는 사유가 되지 않는다.

---

## 1. ✅ 사용 가능 — 공유 설화 (전승 자산)

아래는 **특정인의 창작물이 아니라 한국의 전승 설화/전통 도상**이다. 자유롭게 쓴다.

| 범주 | 사용 가능 항목 |
|---|---|
| **존재** | 차사, 저승사자, 열 시왕(十王), 혼(魂)과 백(魄) |
| **장소·공간** | 삼도천, 저승, 서낭당 |
| **사물·개념** | 명부(冥府/名簿), 철삭(쇠사슬), 엽전, 업(業) |
| **도상·미술** | 시왕도, 탱화 도상, 단청 문양, 한복·도포·흑립 |
| **의례** | 천도(薦度 — 죽은 이의 넋을 좋은 곳으로 보내는 의식), 제사, 장례 절차 |

### 왜 안전한가

이 항목들은 **수백 년간 전승된 공유 문화 자산**이다. 특정 창작자의 권리 대상이 아니다.
《신과함께》도, 다른 작품도 이 설화를 **빌려 쓴 것**이지 소유한 것이 아니다.

### 단 하나의 주의

전통 도상을 쓸 때 **특정 작가의 특정 작품**(예: 특정 사찰의 특정 탱화를 그대로 베끼기)을
복제하면 그 작품에 대한 권리 문제가 생길 수 있다.
→ **도상의 문법은 가져오고, 구체적 작품은 베끼지 않는다.**

## 2. ❌ 절대 금지

### 2-1. 영화 《신과함께》

| 금지 항목 | 이유 |
|---|---|
| 캐릭터 이름 — **강림 / 해원맥 / 덕춘** | 창작 캐릭터명 |
| **재판 순회 구조** (7개 지옥을 차례로 통과하며 재판받는 구성) | 이 작품이 대중적으로 각인시킨 **서사 구조** |
| 대사 인용 | |

> ### 🚨 가장 위험한 지점: "저승 재판"을 구조로 쓰는 것
>
> 설화에도 시왕의 심판은 있다. 그러나 **"주인공이 망자를 데리고 재판을 차례로 통과한다"는
> 구성**은 대중에게 《신과함께》의 것으로 각인돼 있다.
>
> **우리 구조는 재판이 아니다.**
> 차사는 **명부에 적힌 몫을 데려오는 '집행'**을 한다. 심판하지 않는다. 변호하지 않는다.
> 선택은 **천도냐 파혼이냐** 두 가지뿐이고, 그건 재판이 아니라 **처결**이다.
>
> **이 차이를 모든 서사 작업에서 의식적으로 유지한다.** (`opus-narrative-lead` 책임)

## 3. 🚨 AI 에셋이 가장 위험하다

> ## **AI 생성 프롬프트에 특정 작품명을 절대 넣지 마라.**

### 왜 가장 위험한가

AI 생성물은 **"어떤 작품을 참조해 만들었는지"가 프롬프트에 기록으로 남는다.**

| 상황 | 결과 |
|---|---|
| 사람이 그린 그림이 우연히 비슷함 | "참조하지 않았다"고 주장할 수 있다 |
| 프롬프트에 "○○ 스타일로"를 넣어 AI가 생성 | **의도적 모방의 증거를 우리가 직접 작성해 보관한 상태**. 방어 불가능 |

프롬프트 기록은 플랫폼에도, 우리 파일에도 남는다. 지워도 "지웠다"는 사실이 남는다.
**애초에 쓰지 않는 것만이 유일한 방어다.**

### 금지 / 대체 어휘표

| ❌ 금지 프롬프트 | ✅ 대체 프롬프트 |
|---|---|
| "신과함께 스타일의 저승사자" | "흑립과 검은 도포, 붉은 띠, 쇠사슬을 든 인물. 저채도 남청색 환경광(`#16213E`), 림 라이트, 도포 자락의 수평 흐름 강조" |
| "디아블로 같은 음산한 던전" | "습한 석조 질감, 낮은 키 라이팅(low-key lighting — 어두운 톤 위주로 빛을 아주 적게 쓰는 조명), 안개층, 바닥 반사 억제, 저채도 남청" |
| "도깨비의 세계 같은 도술 이펙트" | "청록 발광 입자(`#5FE3C0`), 한지 질감 궤적, 단청 문양 전개" |
| "탱화 스타일" | ✅ **이건 괜찮다.** 탱화는 공유 전통 도상. 단 **특정 작가의 특정 작품명**은 금지 |

### ✅ 안전한 프롬프트 어휘 3종

1. **전통 도상 명칭** — 단청, 탱화, 시왕도, 흑립, 도포, 철삭, 한지, 서낭당
2. **미술 기법·사조 용어** — 낮은 키 라이팅, 테네브리즘(tenebrism — 어둠 속에서 한 곳만
   강하게 비추는 명암 기법), 림 라이트(rim light — 인물 윤곽선만 빛나게 하는 조명),
   서브서피스 스캐터링
3. **우리 팔레트 코드값** — `#16213E`, `#0F1729`, `#5FE3C0`, `#E85C41`, `#4FA8A0`,
   `#F3E7D3`, `#D4A94E`

## 4. 체크리스트 (에셋/텍스트를 커밋하기 전에 매번 확인)

- [ ] 프롬프트에 **작품명·회사명·작가명**이 들어가지 않았는가?
- [ ] 캐릭터 이름이 기존 작품의 캐릭터명과 **같거나 유사하지 않은가?**
- [ ] 스킬/도술 이름이 기존 작품의 것과 **겹치지 않는가?**
- [ ] 서사 구조가 **'재판 순회'** 형태로 흘러가지 않는가?
- [ ] 주인공 실루엣이 **일본 사신(낫+해골+기모노)**과 혼동되지 않는가?
- [ ] UI 레이아웃을 특정 게임에서 **그대로 따오지 않았는가?**
- [ ] 생성에 쓴 프롬프트를 `assets/**/README.md` 에 **기록했는가?**

## 6. 분쟁 소지가 발견됐을 때의 행동 수칙

1. **작업을 즉시 멈춘다.** 계속하면 손실만 커진다.
2. 해당 에셋/텍스트를 **커밋하지 않는다.** 이미 커밋했으면 `DEVELOPMENT-LOG.md` 에 기록한다.
3. 오너(PD)에게 **채팅 본문으로** 보고한다 — 무엇이 위험한지, 왜 위험한지, 대체안 2~3개.
4. 판단이 애매하면 **보수적으로 간다.** 애매한 걸 밀어붙여서 얻는 이득보다 위험이 크다.
